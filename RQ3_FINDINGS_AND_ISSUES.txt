FINDINGS
--------
F1. CPU granularity: finer task splitting lowers energy modestly and
    monotonically (~6% from N=1 to N=8) with low variance. This is the
    cleanest, most reportable result of RQ3.

F2. RAM granularity: no monotonic energy trend (hump at N=4). The
    uncapped-bandwidth design produces real contention that muddies the
    granularity effect. Should be discussed explicitly in the thesis,
    as the code comments already anticipate.

F3. Sequential reference behaves exactly as expected (N x duration /
    energy), confirming the pipeline measures what it claims.

ISSUES
------
I1. RAM work-equivalence check is NOT valid with the current metric.
    verify_work_equivalence.sh uses stress-ng --vm bogo-ops, which count
    memory allocation cycles. As per-task memory shrinks (8G -> 1G),
    allocation cycles complete faster, so bogo-ops explode with N
    (sequential: 65k / 231k / 2.44M / 5.50M for N=1/2/4/8). The result
    LOOKS like broken work-equivalence but is a metric artifact.
    -> Needs a different RAM work measure (e.g. bytes touched, a fixed-op
    stressor, or documented as unverifiable) before RAM results can be
    trusted for the work-equivalence premise.

I2. Full RQ3 runs are extremely long (~12h wall clock) because the
    nextflow.config executor cap ($local.cpus=4) serializes every run and
    the N=8 sequential tasks are 8x60s=480s each (x2 subsystems x5 reps).
    -> Consider shorter duration for sequential reference, or accept the
    cost; resume via `-resume` works well (cache) but a 2h single command
    timeout was not enough.
