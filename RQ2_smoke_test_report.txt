Bugs found (blocking)
---------------------
1. workflows/granularity.nf:39 — script won't compile.
   GRANULARITY_SWEEP(task_counts.combine(rep_ids)) feeds a tuple channel
   into a process with two separate `val` inputs. Blocks ALL modes since
   Nextflow compiles every workflow up front.
   Fix: declare `tuple val(task_count), val(rep_id)`.

2. \${projectDir} unbound var.
   In mixed_load.nf:63,126 and baseline.nf:29,65,106, \${projectDir} escapes
   Nextflow's interpolation, so bash sees an unset variable → every
   measure_rapl.sh call exits 1.
   Fix: unescape to ${projectDir}.

3. Parallel mode hangs forever.
   mixed_load.nf:119-122 ends the parallel command with a bare `wait`.
   measure_rapl.sh runs an infinite background mem-sampling loop in the same
   shell, so bare `wait` blocks on it indefinitely (>10 min).
   Fix: `wait` only on explicit workload PIDs ($!).

4. Utilization columns empty.
   Completed run has ,, for cpu_util_pct/mem_util_pct although
   measure_rapl.sh prints them — the workflow's grep/parse doesn't extract
   them.

5. IMPORTANT: utilization columns are CORE to RQ2, not cosmetic.
   Per README: cpu_util_pct/mem_util_pct are sampled from /proc as
   independent evidence the workload actually loaded the system, separate
   from the RAPL energy reading. Empty values undermine RQ2's evidence.

6. RAPL validation against turbostat (scripts/validate_rapl.sh) has NOT
   been run on this machine. README requires it once per machine before
   trusting RAPL data (>10% discrepancy = flag). Pending prerequisite.

7. RQ2 analysis path not ready. clean_data.py/stats.py assume the RQ1
   schema (numeric intensity, subsystem grouping). RQ2 uses combination +
   fixed "max" intensity — README says treat RQ2 analysis as manual/ad-hoc.
